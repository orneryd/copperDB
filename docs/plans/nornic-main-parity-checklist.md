# NornicDB Main Parity Checklist (Storage-Centric)

Documentation status note: copperDB's supported runtime architecture is currently single-node only. Any distributed, fabric, replication, remote graph-read, or cluster-search items in this checklist are parity backlog and future architecture notes, not a current product/runtime guarantee.

## Major storage architecture/features detected upstream

### Core engine and API surface
- [ ] Engine interface parity (node/edge CRUD, traversal, schema, bulk ops, stats)
- [x] Optional extension interfaces parity (prefix stats, adjacent edges, namespace schema provider)
  Adjacent-edge baseline now exists in `crates/storage::StorageEngine::get_adjacent_edges`, and local eval plus replication graph-read paths use that unified storage read path for outgoing/incoming/both relationship expansion. Prefix stats now use maintained namespace node/edge counters instead of full-tree scans for namespace prefixes, namespace label-cardinality stats are maintained with node writes, and namespace schema provider parity now has a dedicated namespace-scoped schema keyspace plus snapshot API instead of treating the global catalog as implicitly isolated.
- [x] Streaming APIs parity (storage now has callback-based node, prefix-scoped node, edge, and node-chunk streaming baselines that walk storage iterators without materializing the whole store, those callback streams treat `StorageError::IterationStopped` as normal early completion, and the storage, namespaced-storage, and async-storage stream surfaces now also accept an explicit `RequestCancellation` handle for cooperative external stop; ingress-rooted request/mesh-wide context propagation from [request-cancellation-propagation.md](request-cancellation-propagation.md) remains implementation work)
- [x] Prefix delete / namespace deletion parity (storage now exposes structured `delete_by_prefix`, rejects empty prefixes, reports deleted node/edge counts, removes matching records through index-aware delete paths, and clears namespace stats plus namespace-scoped schema metadata for namespace prefixes)

### MVCC and lifecycle
- [x] MVCC version/head model parity (baseline in `crates/storage::MvccStore`; current reads are now pinned to a per-key current head while archived historical versions stay off the hot index path, retained-floor anchoring avoids sparse post-prune ghost-chain reads, and the storage baseline exposes Nornic-style lifecycle pause/resume/schedule/debt inspection controls)
- [x] Snapshot-visible read selectors parity (snapshot timestamp reads in `MvccStore::read`, plus real `StorageEngine` and `NamespacedStorageEngine` snapshot-visible node, label, edge, and edge-type reads backed by the storage-owned MVCC path instead of collapsing to current-state-only behavior)
- [x] MVCC pruning/rebuild lifecycle parity (prune_mvcc_versions supports explicit max_versions with reader-anchor preservation; trigger_prune_now safe-guarded to only advance floor when active readers exist, never removing versions)
- [x] Snapshot reader registry parity (tracked snapshot leases now pin the oldest active reader and pruning respects that floor)
- [x] Lifecycle debt/scheduling controller baseline parity (lifecycle status now reports active readers, retained-version debt, safe prune-now behavior, and the storage-owned prune surface now also exposes explicit per-key `MvccPruneOptions` through `MvccStore`, `StorageEngine`, `NamespacedMvccStore`, `NamespacedStorageEngine`, and `db.storage()`)

### WAL and durability
- [x] WAL engine wrapper parity (baseline in `crates/storage::WAL`)
- [x] WAL segmenting, diagnostics, degraded mode baseline parity (segment stats, corruption/degraded signaling, and persisted compaction-truncation baseline)
- [x] Snapshot + compaction orchestration baseline parity (WAL can now compact/truncate through a persisted sequence boundary while preserving replay order and next sequence across reopen)
- [x] Atomic record/batch replay parity (baseline batch append/replay in `WAL::append_batch/replay_after`)

### Async engine
- [ ] Async write-behind cache parity (bounded baseline now includes timer-driven auto-flush plus cache-pressure-triggered synchronous flush thresholds for pending node and edge buffers)
- [x] Flush hold/flush result parity (bounded baseline: structured flush results, explicit `try_flush`, and flush holds that block both manual and background flush paths)
- [ ] Async cache index maintenance parity
- [x] Async count/read-path consistency parity (bounded baseline: pending-aware prefix or namespace-label counts, current label or edge-type reads, merged `all_nodes` or `all_edges`, callback node or edge streaming, prefix-scoped node streaming, and chunked node streaming over the wrapped storage surface, all with Nornic-style early-stop support via `StorageError::IterationStopped`)

### Schema and constraints
- [x] Constraint contracts (unique/existence/node-key/type/relationship) parity (baseline types in `ConstraintType`)
- [x] Constraint validation and namespaced validation parity (baseline unique/exists/node-key checks in `SchemaManager`)
- [x] Schema persistence/index catalog parity (baseline persistence in `StorageEngine::persist_constraint/load_constraints`)
- [x] Knowledge policy schema hooks parity (storage now persists decay bindings, promotion-policy targets, typed `ON ACCESS` mutations, and per-entity access metadata)

### Indexing and query support
- [ ] Label/edge/property/range/temporal index parity
- [ ] Deindex enqueue/worker/cleanup parity
- [x] Prefix/namespace stats parity (storage now maintains namespace node/edge counters and namespace label-cardinality counters at node/edge mutation time; namespace-prefixed count APIs use those counters for fast per-database stats)
- [ ] Embedding pending-index parity
- [ ] Per-database search/index/embedding config parity. copperDB should treat Cypher schema DDL as authoritative per database: if a database defines property, RANGE, TEMPORAL, FULLTEXT, or VECTOR indexes in schema, those declared indexes should still load, rebuild, and maintain on open for that database. "Automatic" search/index/embedding work means extra implicit or background-created indexing beyond declared schema, and that automatic work stays disabled by default unless a database explicitly opts in. The CLI flag remains the hard global kill switch for all indexing work, matching NornicDB's emergency override semantics.

- [x] Conflict handling/message parity (baseline NornicDB-compatible error messages in `crates/txsession`)
- [ ] Namespace-pin transaction semantics parity
