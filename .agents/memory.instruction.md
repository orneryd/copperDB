# Coding Preferences
- Keep parity-tracking docs current as transport and auth slices land.
- Prefer focused deterministic cargo tests scoped to the touched crate or behavior.
- Keep automatic indexing or search work disabled by default; schema-declared indexes remain authoritative per database.
- Plan local embedding work against NornicDB's llama.cpp path, not `mistral.rs`: preserve multi-model loading and env passthrough for context, pooling, attention, and flash-attn settings, and keep the llama.cpp pin aligned with NornicDB.

# Constraint Enforcement Architecture
- Storage `Constraint` has `type_name: Option<String>` with `#[serde(default)]` for Type constraints.
- `check_node_constraints` handles: Unique, Exists, NodeKey, Type (via `value_matches_type`).
- `check_relationship_constraints` handles: Unique, Exists, RelationshipKey (= ConstraintType::Relationship in storage), Type.
- Types validated: INTEGER, FLOAT, NUMBER, STRING, BOOLEAN, NULL, LIST, MAP, DATE, DATETIME, POINT.
- Relationship constraint checks run BEFORE edge persistence in CREATE path.
- MERGE relationship path creates edges with empty props, then applies ON CREATE SET afterwards — constraint checking at creation time uses empty properties.
- NornicDB reference: `pkg/storage/badger_constraint_validation.go` — validateNodeConstraintsInTxn.

# Vector Index Options
- Vector index options (`vector.dimensions`, `vector.similarity_function`) are stored separately from `IndexDefinition` via `persist_index_options`/`load_index_options` in storage.
- The `IndexDefinition` struct was NOT modified — adding a field would require updating 100+ construction sites.
- Options are persisted at `CREATE VECTOR INDEX ... OPTIONS {indexConfig: {...}}` time and cleaned up at `DROP INDEX`.
- Query-time consumption of options (in vector search procedures) remains future work.

# Temporal & Domain Constraints
- `ConstraintKind::Temporal` and `ConstraintKind::Domain(Vec<Value>)` added to cypher AST.
- `ConstraintType::Temporal` and `ConstraintType::Domain` added to storage.
- `Constraint.allowed_values: Vec<Value>` field for domain constraints.
- Cypher syntax: `REQUIRE (n.key, n.from, n.to) IS TEMPORAL [NO OVERLAP]` and `REQUIRE n.prop IN ['a', 'b', 'c']`.
- Enforcement: temporal overlap detection (non-null key, overlapping ranges fail), domain value membership check (null allowed).
- NornicDB reference: `pkg/storage/badger_constraint_validation.go` cases `ConstraintTemporal` and `ConstraintDomain`.

# Project Architecture
- Remove anything considered legacy. it is vestigial since this is a new project that is not released yet. Any plan changes to architecture are considered refactor to clean architecture that are not backwards compatible until a 1.0 release
- copperDB is a Rust Cargo workspace mirroring NornicDB ../NornicDB package structure under `crates/`.
- Distributed/fabric/replication transport is retained as future-state scaffolding only; do not document it as current runtime support even where tonic/auth/read-fence experiments exist.
- Config and multidb own per-database effective config resolution; engine and server consume that for ranked-search gating.

# Solutions Repository
- For oversized Rust crate roots, prefer extracting one cohesive production module at a time and moving inline tests into `src/tests.rs` following the `crates/cypher` pattern; validate immediately with a focused `cargo test -p ...` and clear any warnings in the touched crate before moving on.
- For upstream Cypher CALL-filter parity, `elementId(...)` must be available in `crates/filter` alongside `id(...)` because `CALL ... YIELD ... WHERE elementId(node) = $param` is a real mirrored shape; validate it with a focused `copperdb-eval` regression rather than parser-only coverage.
- Fulltext CALL alias parity should stay bounded to declared schema indexes: `db.index.fulltext.queryNodes('default'| 'node_search', ...)` may fan out across catalogued node fulltext indexes, but should not imply automatic indexing when no fulltext schema index exists.
- For small built-in procedure parity (`db.labels`, `db.relationshipTypes`, `dbms.procedures`), keep execution local to `crates/eval/src/eval_engine_policy.rs`, return deterministic sorted rows, and let the existing CALL/YIELD/WHERE/RETURN pipeline enforce projection and bad-column behavior.
- When aliasing or merging ranked fulltext CALL results, preserve first-seen rank as the tie-breaker for equal scores; otherwise `{skip, limit}` regressions on explicit indexes become unstable.
- For introspection procedures (`db.constraints`, `db.indexes`, `db.info`, `db.ping`), reuse the storage-level `load_constraints()`, `load_index_definitions()`, and count APIs directly; map constraint/index type enums to their Neo4j-compatible string names (`UNIQUENESS`, `RANGE`, `ONLINE`, etc.) and keep column names matching the upstream registry signatures exactly.
- For schema-introspection procedures (`db.schema.nodeProperties`, `db.schema.relProperties`, `db.schema.visualization`), scan all node/edge records once, collect label→property and relation-type→property mappings into sorted `Vec<Row>`, and return `"ANY"` as the propertyType string.
- For `nornicdb.version` and `nornicdb.stats`, return single-row results with hard-coded version/build/edition strings and live counts from `all_node_records()`/`all_edges()` plus deduplicated label/relationship-type sets.
- For `dbms.functions`, maintain a complete catalog of all supported Cypher filter functions with name/signature/description/category matching upstream Neo4j conventions; assert individual function categories in regression tests for correctness.
- For `nornicdb.decay.info` and `nornicdb.knowledgepolicy.info`, derive enabled-state and catalog counts from real storage APIs (`load_decay_profile_schemas`, `load_decay_profile_binding_schemas`, `load_promotion_profile_schemas`, `load_promotion_policy_schemas`); never stub these with hard-coded zeros.
- For `nornicdb.knowledgepolicy.profiles`, iterate bundles then bindings, resolve inherited HalfLifeSeconds and ScoreFloor from the referenced bundle via `profile_ref`, and return all 18 columns matching the upstream registry signature. For `nornicdb.knowledgepolicy.policies`, iterate profiles then policies, deriving Scope from `is_edge` for policy rows. Both procedures use alphabetical `ORDER BY kind, Name` which puts "binding" before "bundle" and "policy" before "profile".
- For `dbms.*` and DB-level introspecton procedures (`dbms.components`, `dbms.info`, `dbms.listConfig`, `dbms.clientConfig`, `dbms.listConnections`, `db.index.fulltext.listAvailableAnalyzers`), return NornicDB-compatible hard-coded configuration rows with column names matching the upstream registry signatures exactly; `dbms.listConnections` returns an empty row set as expected for single-node operation.
- Cypher `CALL` procedures are owned by `crates/eval/src/eval_engine_policy.rs`; `db.index.vector.queryNodes` now uses the index catalog as the single runtime path and resolves vectors with Nornic precedence: `named_embeddings[property]` first, then property-backed numeric arrays, then managed chunk embeddings.
- `RETURN ... AS alias ORDER BY alias` must resolve through RETURN aliases back to their underlying expressions so the sort operates on pre-projection rows. The fix lives in three places: `sort_rows_by_return_order` (uses `return_alias_map` + `resolve_order_expression`), `sort_rows_by_with_order` (same), and `optimized_order_key` (must handle `PropertyAccess` through nested objects, not just dot-keys). Always mirror both the alias form and the variable-reference form in regression tests.
- Parser gap implementations: `+` operator lives in `expression_parser.rs` via `parse_addition` inserted between `parse_comparison` and `parse_primary`, evaluated in `filter/src/lib.rs` as string concat. Pattern existence check is `Expression::PatternExists` parsed via `try_parse_pattern_predicate`, evaluated in `eval_engine.rs`'s `eval_where_predicate` and `check_edge_exists`. Map assignment is `SetItem::MapAssignment` parsed by checking for `=` after variable in `parse_set_item`, evaluated in `execute_set_clause` by merging map entries into node props.
- All known parser gaps are now resolved. Major Cypher expression features supported: `+` operator (string concat), pattern existence `(n)-[:REL]->(m)` via `PatternExists`, `SET n = $d` map assignment via `SetItem::MapAssignment`, `$d.uuid` parameter property access via `Expression::ParameterPropertyAccess`, `SET n:Label` static labels via `SetItem::Label`, `SET n:$(d.labels)` dynamic labels via `SetItem::DynamicLabel`, and `CASE WHEN/THEN/ELSE/END` expressions (both searched and simple forms) via `Expression::Case(CaseExpression)`.
- `CALL` is now a pipeline row source instead of a terminal-only clause: `crates/cypher` parses optional `YIELD` items onto `CallClause`, `crates/eval/src/eval_engine_policy.rs` projects them with the shared `project_row` path, and `crates/eval/src/eval_engine.rs` lets trailing `RETURN` continue over those rows.
- Alias-heavy procedure coverage should stay grounded in the shared projection path: parser coverage belongs inline in `crates/cypher/src/lib.rs`, and eval regressions should prove `YIELD ... AS ...` variables flow into downstream `RETURN` expressions without assuming separate `ORDER BY` support for RETURN aliases.
- The remaining local vector strategy seam was `copperdb-vectorspace`; keep that crate on a single HNSW-preferred cosine scoring path instead of reintroducing metric switching.
- Documentation policy: copperDB should currently be documented as a single-node execution architecture. Distributed, fabric, replication, mesh, and cross-node transaction material belongs in deferred roadmap or parity-backlog language unless and until that runtime is intentionally enabled and validated.
- For storage parity increments, prefer landing a storage-owned helper and immediately switching one real consumer to it in the same slice; for adjacent-edge parity, `StorageEngine::get_adjacent_edges` plus `cargo test -p copperdb-storage adjacent_edge_queries_respect_direction_and_type_filters -- --nocapture` and `cargo test -p copperdb-eval --lib -- --nocapture` kept the change grounded.
- Namespace schema parity is not a filtered view over the global schema catalog. Use the dedicated namespace schema keyspace and `StorageEngine::schema_for_namespace`; maintained namespace node/edge and label-cardinality counters back prefix/namespace stats.
- Prefix delete parity is implemented as `StorageEngine::delete_by_prefix`: reject empty prefixes, collect matching node/edge ids first, delete through structured record paths to clean indexes/stats, and clear namespace stats plus namespace schema metadata when the prefix is a namespace prefix like `alpha:`.
- Storage streaming baseline uses synchronous callbacks: `stream_node_records`, `stream_node_records_by_prefix`, `stream_edge_records`, and `stream_node_record_chunks`. Those storage and async wrappers now treat `StorageError::IterationStopped` as normal early completion, and storage, namespaced-storage, and async-storage now also expose explicit `RequestCancellation`-aware stream variants for cooperative external stop without conflating that path with callback early-stop.
- Request/mesh-wide cancellation is now partially implemented: the first local slice is the shared `copperdb_util::RequestCancellation` handle threaded through storage-streaming surfaces. Ingress-rooted request contexts, child-context propagation, passive deadline transport, active remote cancel messages, and broader eval/search/fabric/replication checkpoints from `docs/plans/request-cancellation-propagation.md` still remain open.
- Namespace-wrapper parity can land as a bounded storage-owned adapter before async/composite parity: `NamespacedStorageEngine` should prefix node and edge ids on writes, unprefix on reads, delegate counts/schema/delete to the namespace-aware storage helpers, use prefix node streaming directly, and keep edge streaming as a filtered synchronous baseline until AsyncEngine work exists.
- After landing a storage-owned helper, switch one real consumer immediately when practical. For namespaced storage parity, `crates/multidb` was the right first hop: route its catalog through `StorageEngine::for_namespace("multidb")` and stop hand-encoding the namespace into raw IDs.
- MVCC parity should follow Nornic's head/archive split to avoid version-chain cliffs: keep current reads pinned to a per-key current head, archive superseded versions separately so old versions stay off the hot index path, carry a retained-floor anchor in the head after pruning, and keep lifecycle admin controls shaped like pause/resume/schedule/debt inspection rather than burying cleanup state inside ad hoc prune calls.
- For the in-memory MVCC baseline, current-only secondary indexes and historical visible-at reads should be split the same way: keep current label/type indexes free of old versions, maintain separate historical candidate directories for snapshot-visible label and edge-type reads, let prune own cleanup of those historical candidate directories once a label or edge-type only survives below the retained floor, and thread lifecycle controls through a bounded namespaced MVCC wrapper instead of having namespace-aware callers reach back to the raw store.
- When extending MVCC lifecycle parity, prefer an explicit storage-owned prune API with typed options over ad hoc retain-count knobs alone: `trigger_prune_now(...)` can remain the lifecycle shortcut, but real consumers and wrappers should share the same `prune_mvcc_versions(MvccPruneOptions)` path.
- For async-engine parity, start from the storage-owned structured-record seam instead of raw node/edge bytes: a bounded `AsyncStorageEngine` can queue typed node/edge record writes, expose effective current-state reads by overlaying pending writes on wrapped storage reads, overlay pending mutations onto prefix and namespace-label count surfaces, maintain pending label and edge-type inverted indexes so current label or edge-type reads rebuild immediately on update and do not rescan the whole pending cache, and maintain pending start/end adjacency indexes so outgoing, incoming, and typed adjacency reads stay O(degree) across pending edge moves, deletes, and type changes. Delegate MVCC/lifecycle methods through a worker-owned message-passing seam so background auto-flush does not share the sled-backed `StorageEngine` across threads. After timed flushes and cache-pressure thresholds, the next grounded Nornic seams were adaptive flush timing plus cache-only delete callback safety for pending creates; those are now implemented. The current embedding-related seam now includes a persistent `StorageEngine` pending embedding index with refresh, count, mark, requeue, stale-entry cleanup, and `find_node_needing_embedding` support, `AsyncStorageEngine` layering pending-write awareness over that storage baseline with its in-memory queue, `NamespacedStorageEngine` adapting the same queue through namespace-prefixed IDs, storage-owned clear-all-embeddings helpers that strip the current temporary embedding payload and let the pending queue repopulate through the normal put path, and shared `update_node_embedding` helpers across storage, async storage, and namespaced storage that replace the current property-backed embedding payload on existing nodes without changing counts or unrelated fields. The next structural step is to move managed embeddings and embedding metadata out of `NodeRecord.properties` and into dedicated typed structs matching NornicDB's node model; richer lifecycle parity should be built on that typed model rather than further polluting the property namespace. Keep broader async index-maintenance work open until the wrapped storage surface supports it cleanly.
- For the next async parity increments after adjacency, prefer merged export surfaces before inventing new cache shapes: add worker-backed persisted `all_node_records`, `all_edges`, or prefix-scoped node collection, overlay pending creates, updates, and tombstones in a `BTreeMap`, and let callback streaming reuse that merged current-state view. With merged all-reads, prefix node streaming, chunked node streaming, and Nornic-style early-stop sentinel semantics now landed across node and edge streams, the next open async surfaces are true external cancellation modeling and whatever broader write-behind or cache-maintenance parity still lacks a clean storage-owned contract.
- Once that bounded MVCC baseline is stable, embed it into `StorageEngine` rather than leaving it test-only: own an internal `MvccStore`, bootstrap it from current persisted rows on open, mirror structured node and edge mutations into it, expose visible-at plus lifecycle methods on the real storage surface, and delegate the same shape through `NamespacedStorageEngine` so engine-facing callers can reach it via `db.storage()`.
- For storage-owned MVCC lifecycle repair, prefer an explicit guarded rebuild control over a fake transport-time snapshot shim: if current persisted rows and in-memory MVCC drift, expose `rebuild_mvcc_from_current_state()` on `StorageEngine`, block it while active readers exist, reset the in-memory MVCC state, and replay persisted current rows through the same typed storage path.
- Layer 4 now has a narrow routed simple-match fast path: `detect_query_pattern` classifies single-node `MATCH (n:Label) RETURN n LIMIT k` queries as `SimpleMatchLimit`, and `EvalEngine::execute_with_routes` handles that shape with label-backed early-stop retrieval. Keep broader `MATCH ... LIMIT` forms, trace parity, and other hot paths open.
- Parser-approved pipeline routing now includes a basic `UNWIND ... MERGE ... RETURN` batch-upsert shape by admitting `MERGE` in `pipeline_probe` and reusing `execute_merge_clause` from the routed pipeline executor. Broader UNWIND batch and trace parity still remain open.
- `EvalEngine` now owns per-engine `HotPathTraceState`, resets it per `execute`/`execute_with_routes` call, and currently marks at least the narrow simple `MATCH ... LIMIT`, current compound create/delete relationship fast path, node `MERGE` schema-lookup versus scan-fallback behavior, seeded `UNWIND ... MATCH ... CREATE`, and basic `UNWIND ... MERGE ... RETURN` routed batch shapes. Tests can assert flags through `hot_path_trace_snapshot()`.
- Distributed transaction-time architecture is now explicitly hybrid: keep Dynamo-quorum replication for data durability and routing, but move authoritative begin/commit/read-fence allocation for distributed MVCC snapshot isolation and RYOW onto a separate transaction-time oracle seam. Paxos v2 is the target distributed oracle implementation; the current local logical clock remains the default fallback allocator and merge helper.
- `txsession` now treats inbound bookmarks as transaction-time fences: required bookmarks must parse as `LogicalTransactionId::stable_id()` values, optional bookmarks ignore invalid entries, begin timestamps advance through `TransactionTimeOracle::observe`, and commit/session commit can return a normalized bookmark string for downstream RYOW propagation.
- `txsession` now also persists the effective session read fence and normalized bookmark set, `copperdb-engine` exposes `begin_transaction` plus `transaction_read_fence`, and the distributed graph-read seam (`replication` + `nornicgrpc`) now carries an optional `read_fence` field on remote graph-read requests even though remote enforcement is still pending.
- Fabric ranked-search and hydration now mirror that transport seam: `copperdb-search` carries optional `LogicalTransactionId` read fences through ranked-search and hydration transports, `nornicgrpc` serializes them on `RemoteRankedSearchRequest` and `RemoteHydrationRequest`, and current engine/server callers still pass `None` until session-derived propagation is wired.
- The server-owned fabric ranked-search admin route is now the first real non-`None` caller: it accepts bookmark strings on the request body, resolves a single read fence through `copperdb-txsession`, and forwards that fence through both ranked-search fanout and hydration fanout. Broader session-owned propagation and remote fence enforcement are still pending.
- Server-owned distributed read routes now derive their effective read fence through real `txsession` state instead of standalone bookmark parsing: both Neo4j-compatible distributed `tx/commit` reads and the fabric ranked-search admin route start a read transaction from request bookmarks, read back the effective fence, clean up the transaction, and forward that derived fence through engine distributed graph reads or ranked-search plus hydration fanout.
- Remote data-path gRPC read handlers no longer drop forwarded read fences on the floor. The current server-side enforcement step is a serving-node causality barrier: local graph-read, ranked-search, and hydration handlers observe the forwarded `LogicalTransactionId` through a short-lived `txsession` read transaction before serving current-state storage reads. This is not full snapshot-materialized MVCC enforcement yet; historical graph reads still need snapshot-aware storage/replication APIs.
- Internal gRPC auth is split by method: replica apply/read validate admin JWTs from the unified auth core via `authorization`, while ranked-search, hydration, and distributed graph-read RPCs use forwarded caller auth in `x-copperdb-caller-authorization` so remote nodes can reapply per-database auth without changing protobuf schemas.
- No transport component should auto-load a legacy shared gRPC token from config or env; replica/internal auth is validator-based on the server side, and outbound callers must attach bearer credentials explicitly when that runtime path is implemented.
- Server-owned Neo4j-compatible `tx/commit` writes now build a real outbound tonic replica transport from topology peers and mint a short-lived admin cluster JWT when security is enabled; routed read execution now builds the real graph-read gRPC transport and forwards the caller token while clustered access-metadata side effects continue through the admin-authenticated replica channel. Do not fabricate remote peers with `InMemoryReplicaTransport` and `MemoryStorage` in runtime code.
- Server protocol handlers must not drive distributed tonic work through a blocking bridge on the request runtime thread. For current-thread Tokio test contexts, offload Neo4j `tx/commit` distributed execution onto `spawn_blocking` and let the blocking worker run its own short-lived runtime for the routed transport call.
- For server-level distributed graph-read regressions, prefer real tonic peers backed by `LocalEngineReplicaHandler` over bespoke stubs. If the test is only about routing and not auth forwarding, disable peer auth explicitly; otherwise supply a real forwarded caller token.
- Startup gRPC cert hardening currently includes certificate validity-window rejection plus cert-or-key pair consistency validation in config before listener bind.
